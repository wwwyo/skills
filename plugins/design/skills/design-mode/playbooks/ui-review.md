# UI review

UI の変更をレビューする。出力は must / should / nit と、最後に判定を 1 行書く。

1. **見た目を確かめる。** 変更前後のスクリーンショットを撮る。撮れないときは、読むだけのレビューだったと書く
2. **token と方向。** `design.md` の token から外れた値、**unslop** が挙げる AI っぽさの兆候を見る
3. **崩れ。** **break-ui** の最悪のデータで崩れないかを見る
4. **動き。** 動きの変更があれば **review-animations** の基準で見る
5. **モバイル。** モバイル向けなら **mobile-native** の項目を見る

見た目の好みは指摘しない。誰が・いつ困るかを書けるものだけを指摘にする。
